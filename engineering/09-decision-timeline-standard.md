# Decision Timeline Standard

Every result card must include the existing five-step student-facing decision timeline. It shows the sequence used to produce eligibility and interview guidance without exposing implementation details.

## Required timeline

Use exactly five steps, in this order and with these titles:

1. Applicant details checked
2. Eligibility assessed
3. Selection model applied
4. Historical guidance compared
5. Interview recommendation produced

Do not add, remove, rename, or reorder steps.

## Content rules

- Use student-facing wording throughout.
- Explain the applicant details and pool used.
- Explain the eligibility outcome.
- Describe the university-specific selection model in plain language.
- State that historical guidance comes from previous admissions cycles.
- Explicitly state that historical guidance is not a guarantee of an interview.
- Identify any ApplySmart predictive estimate as an ApplySmart estimate, not an official university threshold.
- Explain the final interview recommendation or the higher-priority state that prevents one.
- Apply not-eligible, manual-review, and insufficient-evidence precedence consistently.
- Do not include offer prediction.
- Do not use technical implementation wording.

When a stage cannot be applied, use the existing status and explanation conventions rather than fabricating a result. The timeline must not change the recommendation or evidence confidence calculated elsewhere on the result card.

## Verification

The timeline must be generated by the shared builder and pass:

```sh
node scripts/test-decision-timeline.js
node scripts/test-completed-result-cards-regression.js
```

The dedicated university regression must assert that the selection-model summary accurately reflects the official implemented method and, where applicable, that any ApplySmart predictive estimate is labelled consistently with the [Evidence-Based Interview Prediction Standard](11-evidence-based-interview-prediction-standard.md).
